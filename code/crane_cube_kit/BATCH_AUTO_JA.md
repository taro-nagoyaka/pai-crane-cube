# 姿勢を変えた教師データの自動収集

この機能は学習済みモデルを実行するものではありません。MoveIt教師で
接近・把持・持ち上げ・直立・保持を実行し、成功条件を満たした試行を収集します。
元の raw_auto_branch / data_branch / outputs は変更しません。

## 最初の確認

既存Gazebo・教師・モデルサーバーをそれぞれ Ctrl+C で終了します。
コンテナ pai_ros2 のターミナルで、仮想環境を使わず実行します。

```bash
cd /home/ubuntu/crane_cube_kit
bash collect_batch.sh --out raw_auto_varied --episodes 1 --max-attempts 3
```

ビルドからGazebo起動、教師実行、成功判定、保存、Gazebo終了まで自動です。
デスクトップのGUIも毎回起動します。ブラウザで最初の動作を観察してください。
画面の初期化や描画の準備に時間がかかる場合があります。
準備中は5秒ごとに、関節・カメラ・新鮮な観測・arm・gripper・cubeの受信状況を
実行画面へ表示します。Falseが続く項目で待っています。
ROSの通信をlocalhostに強制せず、コンテナの通常設定を使います。
Ctrl+C時はROSを二重終了せず、中断結果をログに残します。
最初に標準動作が1件保存できることを確認してから、次に進みます。

```bash
bash collect_batch.sh --out raw_auto_varied --episodes 24 --max-attempts 48
```

`--episodes` はこのフォルダ内の保存成功件数の合計目標です。上の例なら追加23件。
Ctrl+Cで中断しても保存済みデータは残り、同じコマンドで残りを収集できます。
最大試行回数に達した場合も、同じコマンドで続行できます。
目標に到達済みなら追加試行しません。失敗を成功扱いして件数を埋めることはありません。
同じ出力フォルダを複数の収集プロセスから使うと、ロックで停止します。

## 動作の変化

4種類を順番に使います。nominal / near_home / lift_recovery / both。

- 既存の標準軌道。
- home近辺で関節角を最大0.06 rad程度変えた姿勢から、開いて接近する軌道。
- 把持後、少し持ち上げた高さで手首のピッチを最大0.10 rad変え、正しい向きへ戻して上昇する軌道。
- 上の2種類を組み合わせた軌道。

最初の4試行は既存のキューブ位置を使用し、以後はXYをそれぞれ最大4 mm変えます。
教師の接近・把持目標も同じキューブ位置から計算します。
閉じ角度、関節制限、負の肘分岐制約は維持します。
関節の動かし方が変わるので、成功してもフレーム数は239固定になりません。
これは失敗姿勢からの回復を広げる第一段階で、失敗したモデルの全状態を網羅するDAggerではありません。

## 自動保存の条件

Gazeboの `/world/default/pose/info` から名前が `woodcube` のモデルだけを読みます。
ROS TF変換で名前が欠落する環境を避けるため、同梱CLI `ign topic` の出力を読みます。
別ワールド・座標系・名前を誤認しないよう初期位置も検査します。

- 教師の計画・実行が終了している。
- 最後の直立姿勢で、キューブが初期高さから15 cm以上上がっている。
- キューブが手首から18 cm以内、手首からの水平距離6 cm以内で、手首より2 cm以上下がっていない。
- アーム4関節が直立から各0.08 rad以内、グリッパが開いていない。
- 最後の2秒以上、キューブの移動が2.5 cm以内。
- 画像・関節・キューブ位置が新鮮で、10 Hzの欠落・関節制限違反・0.15 radを超える教師指令の飛びがない。

判定v2では、画面で把持成功を確認した試行の手首距離14.2088 cmを、
旧10 cm制限が誤って除外していた点を修正しました。
endtipは手首であり、指先やキューブ中心ではありません。
18 cmの範囲へ変更するとともに水平距離6 cmの条件を追加し、上昇・直立・保持・
記録品質の条件を残しています。結果JSONには最終キューブ位置と手首位置の平均・差も出します。
これらは高さ・近接・安定保持による選別で、接触力による把持判定ではありません。
キューブがアームに引っ掛かる等の例外を完全には除外できません。
最初の1件は必ず画面でも確認し、不自然な保持があれば学習に使わず知らせてください。
テスト実行前に、ローカルの純Pythonテストで正常・落下・遠方・低い保持・記録欠落を確認しています。
この作成環境にはROS/Gazeboがなく、実機相当の統合動作はユーザー環境で確認が必要です。
成功判定できない場合は保存せず停止または次の試行へ進みます。

`raw_auto_varied/episode_*.npz` は成功判定済みだけです。
各NPZには通常の学習用配列のほか、段階名・キューブ位置・条件・判定結果も入ります。
除外時も記録できた画像・関節・指令・キューブ位置を、`success=False` の
`batch_logs/trial_XXXXX/rejected_episode_*.npz` に保存します。
正常終了前の記録品質エラーも、記録済み部分を除外データとして保存します。
準備前の失敗等で観測サンプルがない場合はログだけです。
除外データは学習フォルダに混ぜず、変換プログラムも `success=False` を拒否します。
旧版で既に除外した試行は、元の画像・配列が残っていないため復元できません。
`batch_logs/trial_XXXXX/` に理由とログを残します。
`result.json` / `record.log` / `gazebo.log` / `pose_reader.log` が調査用です。
起動・観測エラーが3回連続すると停止します。判定を緩めて成功件数を増やさないでください。

専用のROS_DOMAIN_ID=82、試行ごとに固有のIGN_PARTITIONを使用します。
ユーザーの他プロセスを一括killせず、自分で起動したプロセス群だけ終了します。
同じ時間にモデルのdeployや別の教師を実行しないでください。

## 収集後

```bash
/usr/bin/python3 check_branch.py --raw raw_auto_varied
```

このチェックは肘分岐だけです。NPZ内の自動保持判定とは別です。
次に、元7件と新データを新しいフォルダへコピーし、まとめて変換します。

```bash
/usr/bin/python3 merge_raw.py --inputs raw_auto_branch raw_auto_varied --out raw_combined_v1
source .venv-learning/bin/activate
python convert_dataset.py --raw raw_combined_v1 --out data_varied_v1
```

merge_raw.py は元データを変更せず、出力先が存在する場合は停止します。
同一バイトの重複は除き、同名でも内容が違うファイルは別名で残します。
学習・検証はエピソード単位で分割します。ただし同じ収集器の似た試行なので、
検証MAEだけで性能を決めず、最終的にはGazeboで複数回把持・持ち上げの成功率を確認します。
まず収集が成功したことを確認してから、追加学習へ進んでください。
